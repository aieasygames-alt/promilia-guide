# 上线后的下一阶段开发计划

制定日期：2026-11-14（北京时间）。状态：第 1 轮已完成，实际 main 推送触发自动生产验收 54/54 通过；第 2 轮已交付编辑预览，等待新增稿件真实人工审核。记录见 `DEPLOYMENT-LOG.md`。

依据：`IMPLEMENTATION-ROADMAP.md`、`CONTENT-CALENDAR.md`、`SITE-STRUCTURE.md`，以及最新 `DEPLOYMENT-LOG.md` 和当前代码。旧规划中的“尚无应用代码”等描述属于立项时背景，不作为当前状态。

## 当前基线与固定边界

- 正式主域名 `https://promiliaguide.com` 已上线，SSL 已启用，主域名与别名跳转自动技术验收 54/54 通过。
- 私有 GitHub 仓库连接 Cloudflare Pages；main 发布正式站，其他分支生成禁止索引的编辑预览。保留 Astro 静态输出，不迁移到 Workers。
- 12 篇中日文语言稿已审核发布，首发清单 10/10 就绪；战斗中日文、资源和抽卡简中共 4 篇仍是草稿。第 2 轮战斗稿已进入编辑预览，正式构建继续排除未审核内容。正式构建 34 个 HTML 不等于 34 篇攻略。
- 目录、双语切换、Pagefind 搜索、准备清单、来源与事实校验、译文修订检查、发布门槛、预览工作台和自动测试均已有实现，后续在此基础上扩展。
- CMS、站内账号、评论均不开发，也不为其预建后台。内容、实体资料继续用文件与 Git 维护。
- 页面语言、游戏地区与版本分别建模；不把测试结论、预约入口或日期到来当作正式服状态。
- 新事实、新攻略与译文仍需证据和真实审核。此前人工审核确认仅覆盖当时的稿件，不能自动覆盖后续新增内容。
- 本计划不自动创建定时任务、发布社区消息、开通收费服务或收集搜索词等访问数据。

## 第 1 轮：上线收尾与发布闭环

读者从任何正式入口进入时，都到达正确语言和路径的主域名页面；维护者能确认新版本部署后仍正常。

交付范围：

- 将生产 `promilia-guide.pages.dev` 永久跳转到主域名，保留路径与查询参数，避免误匹配分支或历史预览地址。
- 接入可选 `www.promiliaguide.com` 并跳转到根域名；实施前检查是否出现新的现有记录或服务，再处理具体 DNS 变更。
- 修正双语更新页中“人工审核仍待完成”的过时展示，并记录主域名上线事实。本站修订与官方公告分开表述。
- 在确认生产部署成功后运行正式主域名验收，给出部署对应提交、结果与报告；不靠固定等待时长判断构建完成。
- 记录回滚步骤、可用的生产版本和验收路径；先用预览验证操作，避免仅为演练中断正式站。

验收标准：

- [x] 正式默认域名与 www 对中文、日语深层页面及带参数链接正确跳转，没有循环。
- [x] 主域名 200，原有 HTTP→HTTPS 行为正常，未知页面返回真实 404。
- [x] 分支预览仍可访问，保留 noindex 和空 Sitemap，未跳入生产域名。
- [x] 双语公开更新信息与真实审核、上线状态一致，已在正式站验证。
- [x] 一次实际 Git 推送触发部署后验收；检查失败可定位原因，保留可回退版本。

## 第 2 轮：双语战斗入门（预览交付，待审核）

读者从首页或系统目录进入一篇能解释基本操作、前提与限制的战斗指南，并可继续阅读相关准备内容。

交付范围：

- 优先补齐现有战斗中日文草稿，整理基础操作、已确认机制与常见误区。
- 逐项记录证据、地区与版本；只有测试资料时，标题和结论明确为测试版参考。
- 将战斗指南接入系统目录、首页相关入口与当前语言搜索，补上下文内链。
- 内容不足以支持元素表、数值或配队结论时，保留未知，不编造完整表格。

验收标准：

- [x] 读者能根据正文完成一次战斗记录或技能未触发排查，页面有独立实用价值。
- [x] 预览已接入系统目录、首页入口、双语切换、当前语言搜索与移动端阅读路径。
- [ ] 中日文均完成各自真实人工审核，事实引用、版本和修订关系正确。
- [ ] 审核完成后通过正式构建并进入正式站；当前正式构建仍排除战斗稿。
- [x] 无法满足证据或审核条件的内容继续保留草稿；未编造元素表、数值、配队或资源成本。

## 第 3 轮：开服状态与首日行动

读者选择游戏地区和设备后，能判断当前可做什么，并进入正确的官方下载、准备或首日指南。

交付范围：

- 扩展现有事实与分发数据，明确“日期已公布、时间待公布、预下载开放、正式开放、异常待核验”等状态的证据要求。
- 已确认小时才展示倒计时，同时注明时区；计时结束不自动宣称服务器开放。
- 新公告出现时同步日期、下载、平台、配置和准备清单，复用现有影响报告定位关联译文。
- 首日路线、资源规划、抽卡规则分别作为独立内容任务处理，先维护核验清单，证据与审核齐全后逐篇发布。
- 首页按真实已核验状态调整行动入口，不仅按日历日期切换文案。

验收标准：

- [ ] 同一地区状态在首页、文章摘要与设备速查中一致；中日文信息不会混用服务器规则。
- [ ] 预约、预下载与公开客户端入口准确区分，设备条件不符时不出现错误按钮。
- [ ] 新证据改变关键规则后，过期事实和未同步译文被现有发布检查拦截。
- [ ] 没有官方小时、概率、保底或资源成本时，公开页面不展示猜测值。

## 第 4 轮：逐篇补齐奇波、家园与探索

每个主题单独交付一条“目录进入 → 完成操作判断 → 查看来源 → 继续相关攻略”的阅读路径。

交付顺序：

1. 奇波玩法：已确认用途、获取或捕捉条件，区分探索、战斗和家园能力。
2. 家园：解锁条件、设施用途与派遣操作；未证实的成本、效率不填。
3. 探索：常用交互、系统解锁前提和容易遗漏的条件，不自建点位地图。

每篇都需达到与第 2 轮相同的证据、审核、语言对应、搜索和手机验收标准。可以先发布已通过审核的简中，日语未完成时保持真实的缺译文行为，不生成空译文。主题排序可随可靠资料到达情况调整。

## 第 5 轮：首批角色与奇波资料

读者可以在目录里查到有来源的名称、定位与用途，并进入少量完整详情。

交付范围：

- 建立实体的稳定 ID、分语言名称与别名、地区/版本、来源、已确认字段和未知字段。
- 先做角色目录和 1—3 个证据充分的角色详情；奇波先做有实质介绍的目录，详情按独立阅读价值补充。
- 复用既有来源、修订、发布检查和当前语言搜索，将实体与系统/攻略互相连接。
- 展示图片前核对使用依据；资料不足时采用文本介绍。

验收标准：

- [ ] 同一实体跨语言身份一致，别名可检索，未确认专名不伪装成官方译名。
- [ ] 详情能解决具体问题，不能只有名字和图片；空详情不生成可索引页面。
- [ ] 来源变化可定位受影响页面，新增数据不绕过既有发布门槛。
- [ ] 不开发强度榜、伤害计算器、全量装备数据库或交互地图。

## 第 6 轮：反馈、搜索发现与手机体验

拆成三个可分别交付的小任务：

### 6A：可实际到达的纠错渠道

接入站长明确提供的邮箱或外部反馈入口，保留现有整理、复制和下载能力。中日文都清楚说明提交方式与成功边界，不显示虚假的“已发送”。不要求读者注册本站账号。渠道尚未确定时先完成页面适配，不擅自公开个人邮箱。

验收：从文章携带页面地址进入反馈，用户可通过指定渠道交付问题；空内容、错误地址与渠道不可用时有明确提示。

### 6B：抓取与搜索需求基线

主域名归一后，在已授权且可访问的站长平台验证站点并提交 Sitemap，记录抓取和索引结果。先按语言观察真实查询、曝光与点击，再决定新增选题。流量统计方案另行明确实际用途；原始站内搜索词不默认上传。

验收：验证与提交有实际结果记录，索引异常能定位到页面；不承诺固定收录时间或排名。

### 6C：移动端性能与阅读回归

先测中文/日语首页、长文章、搜索和设备速查的移动端基线，再修复实际发现的首屏、布局、长表格或交互问题；补实际设备和目标网络结果，避免仅为测试分数重构已有组件。

验收：核心任务在窄屏和键盘下可完成，搜索能命中核心名称及别名，筛选与本地清单行为正常；性能报告注明实验室测量条件，有真实访问数据后再评估 Core Web Vitals。
