# Promilia Guide 多语言首版方案

更新日期：2026-11-14，北京时间。

已确认：用户已购买 `promiliaguide.com`；部署目标为 Cloudflare Pages。首版语言调整为简体中文和日语，韩语后续评估。英文整站和此前的英文试点不再占用首版排期。本次取消独立繁中版本，仅保留繁体名称搜索兼容；本文替代此前三语言安排。

## 1. 语言与目标读者

| 语言 | 目录 | HTML lang / hreflang | 首版定位 |
|---|---|---|---|
| 简体中文 | /zh-hans/ | zh-Hans | 事实整理基础稿、开服与开荒指南 |
| 日语 | /ja/ | ja | 发行状态、平台、下载、游戏系统入门 |
| 韩语 | /ko/，仅预留设计 | ko | 后续按真实需求与维护能力发布 |

中文页面使用 zh-Hans；繁体名称仅作为搜索别名，不生成繁中路由、切换入口或 hreflang。日语使用 `ja`，韩语使用 `ko`。语言与游戏服务器是独立维度。

主品牌采用 Promilia Guide，中文副标题可沿用「星原旅伴」。本轮已通过日本官网和 Yostar 原文核验日文游戏名「アズールプロミリア」与「キボ」，首页标题、导航和术语表已更新；Azur Promilia 保留作英文名称与搜索别名。其余角色或系统名仍逐项核对，不直接把搜索拼写视为官方名称。

## 2. URL 与切换行为

```text
https://promiliaguide.com/                         语言选择页
https://promiliaguide.com/zh-hans/                 简体首页
https://promiliaguide.com/ja/                      日语首页

/{locale}/guides/launch/
/{locale}/guides/global-release/
/{locale}/guides/download/
/{locale}/guides/platforms/
/{locale}/guides/requirements/
/{locale}/guides/getting-started/
/{locale}/systems/combat/
/{locale}/characters/{stable-slug}/
```

locale 与 slug 分开管理，各语言可共享稳定的英文 slug；实体依靠稳定 ID 关联，不通过译名拼接关系。站点尚未上线，直接从第一版采用语言前缀。

- 根路径提供简短语言选择页，作为全站首页集合的 x-default；它不承担完整攻略正文。
- 不按 IP 强制跳转；可以建议浏览器语言，并保存用户手动选择。
- 有对应译文时，语言切换直接到同一文章；没有对应译文时，清楚说明并提供目标语言首页，或提供标明语言的原文链接，不生成伪译文 URL。
- 常规内链留在当前语言；跨语言阅读由用户明确选择。
- `/ko/` 在正式发布前不生成公开页、空目录、语言菜单入口、Sitemap 条目或 hreflang。

## 3. 首版页面预算

把内容主题数量与发布 URL 数量分开计数。各语言只发布完成校对、能独立解决问题的内容。

| 语言 | 公测前目标 URL 数 | 覆盖顺序 |
|---|---:|---|
| 简体中文 | 18—20 | 发行/准备 9 页、核心系统 4 页、首页、少量角色、奇波与更新入口 |
| 日语 | 8—10 | 首页、发行地区与日期、下载、平台、配置、准备、战斗入门，再补奇波/家园 |
| 合计 | 26—30 | 不含根语言选择页和编辑规范等辅助页 |

最小双语共同集合为 8 个主题：首页、公测日期、全球/国服发行状态、下载、平台、配置、开服准备、战斗入门。资料不足以形成独立页面时允许合并，数量不能凌驾于内容质量。

11/17 首次上线目标为每种语言 5—8 个实质页面，总计约 10—16 个语言 URL；11/25 前再扩充到上表范围。各语言按内容与校对进度发布，不要求所有主题同时具备译文。

若校对速度不足，保留两种语言，减少次要角色与深度攻略数量。未校对版本留在草稿，不以无审核翻译补数量。

## 4. 地区与发行说明

游戏内容独立记录 `gameRegion`、`gameVersion`，页面独立记录 `locale`。例如日语文章可以介绍国服测试资料，但必须显著说明资料来自中国大陆服及适用版本。

- 11/26 的日期按官方核验的发行范围标注；国服与日本现均有独立原始日程证据，分别引用。其他地区未核验时不套用日期，两地同日也不推断全球同步或跨区互通。
- 下载入口分别注明地区、平台、客户端、商店与账号适用条件；不因界面语言改变下载目标。
- 测试和公测规则分开，抽卡、材料、充值与奖励不跨服套用。
- 原始时间保留时区；日语读者需要时再附 JST。只有原公告给出具体时刻时才换算，不从仅有日期推算开服小时。
- 货币、售价和购买条件不随翻译自动换算或改写；首先说明适用服务器。

## 5. 翻译与术语流程

### 共享事实，独立表述

中文基础稿完成来源核验后，按同一内容 ID 制作日语版本。译文共享事实依据，但可以调整说明顺序、查询表达和地区注释。title、description、导航、按钮、错误提示、图片说明和纠错入口也必须本地化。日语按当地读者的搜索方式和习惯重写表述，避免逐字翻译。

### 术语表

按稳定 ID 维护：简体名、繁体搜索别名、日语官方名、官方名状态、原始来源、常用别名和待确认注释。角色、奇波、材料、技能、设施和系统均可复用。

没有已确认日语官方名时，可保留中文原名或已核验的英文名，并标注名称待确认，不自创日文专名当作官方名称。界面截图来自中文客户端时，在日语文案中解释截图对应的操作名称。

### 发布与同步

推荐元数据：

```text
contentId, locale, slug, gameRegion, gameVersion,
sourceRefs[], sourceRevision, translatedFromRevision,
translationStatus, reviewer, reviewedAt, publishedAt, updatedAt
```

`translationStatus` 可采用 draft、reviewed、published、needs-update。基础事实更新时，将相关译文标记 needs-update；不得只更新中文后把其他版本的更新时间一并刷新。

会改变日期、下载目标或资源决策的重大修订，双语同步优先于新增内容。无法及时校对时暂停过时建议或显示明确的待更新状态。

## 6. 多语言 SEO

- 每个语言页面使用自己的 canonical，均指向 `https://promiliaguide.com` 下的正式 URL。
- 真正互为语言版本且已发布的页面，通过内容 ID 生成互相返回、包含自己的 hreflang 集合。
- 首页集合的 x-default 指向根语言选择页。文章集合若简体版已发布，x-default 可指向该文章的简体版；若未发布，则使用该集合中明确配置的已发布默认版本。
- 不把所有文章的 x-default 一律指向首页；同一集合只配置一个 x-default。
- 缺少某个语言版本时，只输出真实存在的版本；不将其他语言首页冒充文章译文。
- 初期在 HTML head 统一生成 hreflang，Sitemap 收录真实 canonical URL，避免同时手写多套映射。
- 双语分别撰写标题、简介和图片说明；正常排版，不把 Trends 的分词空格塞入标题。
- 在 Search Console/Bing Webmaster 中按语言路径观察表现；页面语言不等于查询用户国家，分析时同时看路径、国家和查询。

## 7. Pagefind、字体与构建

- 所有语言预渲染为静态 HTML，继续部署 Cloudflare Pages，无需增加 SSR。
- 正确标注每页 HTML lang，Pagefind 按语言检索；实施时验证当前版本的中文分词和日语查询效果。
- 术语表为当前语言搜索提供名称、别名与必要的原文映射；不把两种语言混在同一结果列表中。
- 覆盖查询：简繁名称、日语名称、英文名，以及关键系统和角色词。
- 采用覆盖简中和日语的系统字体组合，避免首屏下载整套大型 CJK 字体；图片和游戏素材跨语言复用，alt 独立翻译。
- 共享模板与结构化数据，只把差异内容放入各语言文件；构建时校验 locale、实体 ID、来源、翻译版本和语言对应关系。
