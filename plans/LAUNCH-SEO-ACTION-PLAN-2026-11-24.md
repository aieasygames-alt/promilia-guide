## 五、语言与地区的投入

1. 日语优先补容量、下载、首抽这些已经有本站搜索信号的主题。原文以日本运营方和日本客户端为准；中文材料可辅助定位问题，不能替代日本规则。
2. 中文同步准确的下载、日程、领取与账号风险；游戏玩法细节按各地区资料进度补，不为保证篇数机械翻译全部外围信息。
3. 繁中先维护现有发行地区页中的独立官网与商店身份。台湾历史样本有曝光但不足以解释具体查询及页面表现，暂不据此上线整套新语言。后续先取得 country=Taiwan 下目标页查询和繁中客户端证据，再决定语言扩张。
4. 英语、韩语等扩张等待现有两种语言能够持续维护。全球 Trends 的地区指数、BREAKOUT 和增长百分比都不等于绝对搜索量或本站流量份额。

近期编辑时间可暂按约六成用于日语机会页及对应地区采证、三成用于中文与地区规则同步、一成用于检查与观察。该比例只是资源安排建议，重大错误和官方新公告随时优先。

## 六、单页更新方法与内链

玩家进入正文后，应尽快看到针对当前地区的答案，再看到步骤和依据：

1. 一段结论：现在能做什么、适用地区/版本、关键限制。
2. 短表：设备或情形、所需条件、下一步操作；确认时间带时区。
3. 实际步骤：前置 → 操作 → 成功标志 → 失败处理，配必要截图或短视频时间点。
4. 例外、地区差异与就近原文引用；完整来源与修订记录保留在后面。
5. 一至三个明确的下一步入口，锚文本说明要解决的问题。

`requirements` 与 `reroll` 已折叠共享事实，无需重复实施。`getting-started` 等页面仍把较长的跨地区事实摘要放在正文前；下一轮可评估将当前操作结论提前、完整摘要折叠。`download` 的地区设备速查继续放在明显位置，只需防止旁边重复事实抢占阅读路径。

建议的主要路径：

```text
首页 → 下载 → 容量/设备 → 首日任务
                   首日任务 → 奖励领取 → 卡池规则/首抽判断
                   首日任务 → 家园 / 奇波 / 战斗 → 有实际用途的实体详情
```

首页现有重点卡片为日程、发行地区、下载和准备。临近公测可给容量页更明显入口；开服后逐步把日程/预约入口换成首日任务、领取和实际卡点。按事实切换状态，不随日期自动宣布已开服。页尾相关链接改成下一步操作，不追求每篇互链所有主题。

## 八、搜索观察与技术工作

### 内容效果

- 每次实质发布保存日期、URL、contentId、修订号、地区/版本与改动目的。11/23 新稿和后续公测更新分别留注释。
- 开服首周看相关查询是否出现、关键页是否被抓取、是否有真实点击和新问题。GSC 有延迟；当天数据不用于证明效果。
- 在 GSC 分别查看容量、首抽、下载、领取页的页面筛选后查询；记录曝光、点击、CTR、位置及国家/设备筛选范围。兑换码页有点击不代表已知道点击者用了哪个关键词。
- 样本足够时比较前后各 14 个完整且已处理的数据日，再看 28 日。公测带来需求变化，前后增长不能全部归因于编辑；容量、下载、首抽、领取簇分别分析。
- CTR 用同范围点击总数除以曝光总数，不平均逐行 CTR；不同页面曝光不简单相加作为站点曝光。
- 当前站内搜索使用 Pagefind，本地可见功能不等于已收集用户查询。无结果词只有实际接入并说明采集后才能作为数据来源；目前可先整理站长收到的具体问题。

### 技术辅助

- 复查核心 URL 的 GSC 索引/抓取状态，并确认 Sitemap 提交状态。生产 HTML 可索引和提交成功都不等于已收录。
- Sitemap 当前没有 lastmod。后续可为文章增加基于真实 `updatedAt` 的 lastmod 并验收，不统一填写构建当天，不在本轮策略讨论中当作主要增长手段。
- 文章继续保留 Article、BreadcrumbList 和正确的 canonical/hreflang。FAQ 作为可读内容保留，不把 FAQPage 富结果当游戏站流量策略。
- 测量移动端首页、下载、容量和首日页的首屏/表格/操作路径，再按实际结果优化；本次没有测得 CrUX 或 Lighthouse 数据。
- 实体历史曝光可能早于当前 noindex，不作为直接解除详情索引门槛的理由。

不预设“公测前翻倍”“三天上首页”等结果。近期验收：优先页有对应地区的可执行答案、重大错误及时修正、关键页面能被抓取、出现更多相关查询和真实点击；有足够数据后再设增长目标。
