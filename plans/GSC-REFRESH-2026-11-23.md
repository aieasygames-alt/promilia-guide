1. 容量与配置：直接回答容量问题，分地区和平台列确认表，区分商店分发体积与全部安装空间，补iPad、Android内存和跨端FAQ。
2. 首抽：覆盖游戏全称和アズプロ简称，补判断表、首个角色奖励绑定、耗时记录和账号恢复边界。

4. 实体：核验Metsa独立官方资料，扩充Cabbird生态说明；补连接到首抽、奇波和家园指南的入口。用途与性能证据不足的详情继续noindex。
5. 复查：保存本次私有搜索基线，待新稿正式发布后建立完整、同长度的对照期。

## 待审与已审内容的分离

`src/content/guides/`保留已批准的公开稿；`src/content/revisions/`存放本轮6篇待审语言稿。production读取公开稿，`CONTENT_PREVIEW=true`时用同contentId、locale和URL的新修订覆盖预览。CLI、Astro、审核包读取同一选择规则。旧的人工署名不能进入待审修订。

审核前不以合并分支替代正文审核。审核后将认可的修订提升到guides，填写真实审核人、确认日期和两种语言状态，再移除对应revisions文件。实体详情另行审核；缺乏实用用途与版本依据时保持noindex，不能只填署名提高索引数量。

```sh
# 当前公开稿状态
npm run content:status
# 本轮待审修订与同批状态
CONTENT_PREVIEW=true npm run content:status
npm run build:preview
npm run preview
```

Pages分支预览由GitHub推送触发，保持全站noindex。正式站继续使用现有生产分支的已审稿。

## 发布后的观察方案

以实际生产部署成功的日期为起点，剔除发布当天。积累14个完整且GSC已处理的数据日后，比较前后各14天；数据足够后再比较28天。当前9天历史只作早期参考，不将不同天数的总量作为增长率。

- 国家、设备、查询、页面分别分析，不跨独立报表推断对应关系。
- 为requirements、reroll、redeem-codes三个日语URL分别导出查询，观察已有关键词及新增查询的曝光、点击、CTR和排名。
- 容量词组：容量、スマホ、推奨スペック、iPad、動作環境；首抽词组：官方全称/アズプロ加リセマラ；兑换码同时检查シリアルコード、交換コード与ギフトコード。
- CTR由点击总数除以曝光总数，不平均逐行CTR。排名采用同范围的GSC汇总口径；不把页面曝光简单相加当成站点曝光。
- 当前样本小，不设虚构点击提升承诺。优先观察是否持续获得相关查询曝光、是否出现更多真实点击，再判断标题和正文效果。
- 开服和预下载可能改变整体需求，记录官方日程与版本变化，避免将所有增长归因于本轮编辑。

原始GSC文件与具体业务指标仅保存在本机忽略目录`artifacts/gsc/2026-11-23/`，不随public仓库、Pages静态资源或审核包公开。
