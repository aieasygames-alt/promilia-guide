## 先完成一场可复核的战斗

当前没有可引用的正式服战斗实录，因此本页不提供猜测的元素克制表、伤害倍率或最优队伍。你仍可以先完成一次有记录的观察：打开当前客户端显示的教程，记下版本、地区和场景，再按下方步骤记录一次成功和一次未触发的结果。

这篇文章解决的是“下一次该检查什么”，不是替代游戏内教程的技能说明。游戏内名称、按钮和条件出现变化时，以当前客户端为准，并保留截图或视频时间点。

## 第一次记录按这个顺序

1. **固定场景**：记录服务器或地区、客户端版本、任务名称、角色、装备和伙伴；先不要在不同敌人或场景之间比较。
2. **读完提示**：记录操作名称、输入方式、目标条件、距离或范围提示，以及是否要求能量、冷却或其他资源。没有看到明确说明的项目写“未确认”。
3. **做一次基准**：在不改变设置的情况下完成一次操作，记录目标状态、画面提示和结果。成功不等于知道了全部触发条件。
4. **只改一个条件**：第二次只改变目标距离、目标状态、角色、伙伴或设置中的一个，其他条件保持一致。
5. **保存两种结果**：成功、失败和没有触发都保留。只保留成功片段会把偶然结果误写成稳定机制。

建议把记录写成下面这样，方便之后与同版本的实录对照：

```text
地区 / 版本：
场景 / 任务：
角色 / 装备 / 伙伴：
操作与目标条件：
资源、冷却或提示：
结果：成功 / 失败 / 未触发
视频或截图时间点：
重复次数与唯一变化：
```

## 技能没有触发时先排查什么

按影响最大的顺序检查：教程是否完成、任务是否要求特定目标、操作设置是否改变输入、目标是否在范围内、角色或装备是否满足条件、资源或冷却是否足够。每次只排查一项，并把“没有触发”作为有效结果记录下来。

不要因为一次失败就断定技能被削弱，也不要把提高画质、切换角色或更换装备后的结果归因给元素。先回到同一场景，重做基准记录。

## 元素说明需要哪些证据

要写元素名称、触发顺序、作用对象、持续时间或例外，至少要有游戏内教程、当前版本的重复记录，或可核对的官方/公开测试原文。即使画面出现相似颜色，也不能仅凭视觉判断发生了相同反应。

先用这五个字段整理，而不是直接制作克制表：

| 字段 | 需要确认的内容 |
| --- | --- |
| 名称 | 客户端或官方原文中的名称，未确认的译名保留原文 |
| 触发 | 顺序、操作、目标状态与资源条件 |
| 作用 | 目标、持续时间、可否叠加或被清除 |
| 范围 | 地区、版本、测试/正式状态和场景 |
| 例外 | 未触发、抵抗、免疫或与教程不一致的情况 |

测试版旧表必须标明版本；即使重复成功，也不能自动写成公测沿用。

## 哪些内容现在不要下结论

在没有对应证据前，不要发布具体伤害倍率、元素克制表、最优队伍、资源成本、抽卡收益或“必练”结论。旧测试截图、其他游戏经验和单次高伤害片段都不能代替当前版本记录。

完成一次记录后，可以回到[开服前准备清单](/zh-hans/guides/getting-started/)保存地区与客户端信息；设备或输入异常先查看[设备准备](/zh-hans/guides/requirements/)。后续若补到正式教程或公开实录，再按版本更新本页，并让中日文一起复核。
