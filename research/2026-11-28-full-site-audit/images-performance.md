# 全站图片、图片 SEO 与性能审计

审计日期：2026-11-28。范围为当前 production 构建的 92 个 HTML 文件（含 404），52 张 public 图片、305 次 `<img>` 引用；浏览器检查覆盖排除 404 后的 91 个 URL、三种语言及实体详情页。

## 已确认并修复的问题

### 1. 全站字标图片体积偏大

`public/images/logo-wordmark.webp` 在每页页头及页尾复用，原文件为 444×183、108,858 字节。使用现有衍生图进行 WebP 重编码后为同尺寸 51,254 字节，减少 **57,604 字节（52.9%）**。保留透明通道、图像内容及用户提供的 PNG 原件。已比较深色背景合成图，并检查浅色实际页头截图，未发现可见布局或内容损失。WebP 是有损重编码，未声称逐像素一致。

证据：`artifacts/full-site-audit-2026-11-28/images/logo-comparison.png`（左原图、右优化图）及三张移动端截图。

### 2. 旧角色/奇波列表及详情始终请求 1200px 原图

11 张旧实体图片虽均有正确的 1200×1200 尺寸，却缺少响应式图片候选。新增 **22 张 400/800px WebP 衍生图**（总计 670,720 字节部署存储），保留全部 1200px 原件，并通过 `src/data/entity-images.json` 与 `src/lib/entity-images.ts` 提供候选集。中日文旧列表组件、角色和奇波详情路由已接入 `srcset` 与对应布局的 `sizes`；详情首图保留高优先级并增加异步解码。浏览器按视口与像素密度选择候选。

例如 Anais 原图 212,358 字节；400px 为 37,010 字节（减少82.6%），800px 为104,476字节（减少50.8%）。320 CSS px / DPR2 实测选择800px，满足高密度屏幕要求。

列表中的旧实体卡片位于官方公测名册及插图之后，第一张旧卡不应抢占首屏下载。已统一为 `loading="lazy"`。详情首图仍保持高优先级。

按320px / DPR2实测 `currentSrc` 对应的唯一图片文件大小汇总（每个 URL 只计一次；旧值来自修改前静态资产盘点，旧实体使用1200px原图；既有 feature 图片保持同一候选选择）：

| --- | ---: | ---: | ---: |
| 英语首页 | 237,628 | 180,024 | 24.2% |
| 中文角色总览 | 858,428 | 508,474 | 40.8% |

这是**所选图片文件体积比较**，不是页面总传输量、首屏传输量或真实用户速度提升百分比。所有离屏图片滚动加载后才纳入比较。原始表见 `selected-image-byte-comparison.json`。

### 3. 节日图注的地区开服表述容易引起误解

三种语言的节日图注此前强调“不是韩国开服公告”，容易与已经更新的地区服务信息产生混淆。已改为说明图片是节日插画，并请读者依据对应官方公告查看活动安排与地区服务状态；保留版权和来源信息。

### 4. 原图片审计脚本覆盖不足且会误判 lazy 图片

原脚本仅覆盖8个中日文页面，且把未滚动加载的 lazy 图片列为破图。`scripts/audit-image-pages.mjs` 已改为：

- 从当前 dist 自动发现全部发布 HTML URL，覆盖英语、实体详情及法律页面；404单独排除。
- 分别检查1365×900 / DPR1、320×812 / DPR2。
- 实际滚动到可见图片并等待解码后检查破图。
- 保存每图 `currentSrc`、加载状态、渲染宽度和网络资源记录，检测横向溢出。
- 支持 `PERF_OUTPUT` 保存JSON，`PERF_ROUTES` 指定复测URL。
- 首次加载的LCP/CLS单独采集，避免将审计滚动行为并入初始加载数据。

## 检查结果

- 修改前92个HTML/305次img引用：**0缺alt、0缺尺寸、0缺本地文件、0宽高比失配**。这些项原本已合格，不作为本轮新修复成果。
- 生产站37个实际 `<img src>` 资源进行HEAD检查：全部200，均有正确图片Content-Type。现有Cloudflare缓存为 `public, max-age=14400, must-revalidate`；不存在缺缓存的确认问题，无需对可变路径增加immutable。
- 修改后开发服务：91URL×2视口，共182条检查；181条首轮通过，1条`/ja/systems/home/`移动端因共享开发期间HMR更新导致DOM分离；该URL两个视口单独复测均通过。最终覆盖所有91URL，**未发现破图或横向溢出**。
- 图片布局初始加载CLS观察值均为0。此为本地、不限速、桌面Chromium模拟视口的实验室检查，**不是CrUX真实用户CWV**，并未测量真实INP。并发页面共享浏览器缓存，网络encodedBodySize可能为0，不能把它当作每页冷缓存传输量。
- `npm run check`：0错误，0警告，1条其他组件的execCommand弃用提示（根代理处理中）。未运行或重复完整release suite，由根代理集成验证。
- 390px / DPR2截图检查了英语首页、日文角色总览和中文角色详情：图像比例、透明字标、图片排版和正文宽度正常。
